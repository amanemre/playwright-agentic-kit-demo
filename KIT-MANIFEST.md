# Kit manifest

It records **who owns each file**: the portable kit, the optional `playwright-house-preset`, kit development, or the project that installs the kit. `scripts/kit-files.mjs` holds the same lists in machine-readable form for the installer and the leak check.

Kit version: `0.1.0`

## Modes

### Adopt — an existing Playwright + TypeScript repository

1. Copy the **Kit** files with `node <kit>/scripts/kit-install.mjs --target . --mode adopt` — it never overwrites: an existing file that differs is reported as a collision to merge by hand (constitutions: the repository's instructions first, then the kit constitution with its profile markers); `package.json`, pre-commit and CI changes are reported as patches. `kit-lock.json` records what was installed.
2. Run `kit-tailor` to inspect the repository and write `PROJECT-PROFILE.md`: its architecture, entry points, validation, tags, report style, data formats — each departure from the preset recorded with a reason, or as an open question.
3. Install **Preset** files only when the profile chooses them. Existing tests, page objects, helpers and configuration are not deleted or rewritten; migration toward the preset is a separate approved task.
4. The report structure (DEF-05) is recommended, not imposed; the profile records the project's choice.

### Scaffold — a new project

1. Run `node <kit>/scripts/kit-install.mjs --target . --mode scaffold --area <folder> --project <name>` — it copies the **Kit** and **Preset** files and renders `templates/preset/` (an example page, spec and plan to replace with the app's own).
2. Run `kit-tailor` in scaffold mode to write `PROJECT-PROFILE.md`.
3. The report structure (DEF-05) is a rule; `helpers/util/softChecks.ts` is installed.
